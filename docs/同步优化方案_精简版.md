# 双相机无 PTP 同步优化方案

## 目标

两台相机使用同一个外部脉冲触发，但不支持 PTP。当前需要在**不重构采集流程、不增加复杂 UI、不修改参数计算公式**的前提下，提高双相机帧配对可靠性。

本次修改继续使用现有数据链：

```text
CameraManager
→ CameraFrame
→ DIMM::handleLiveFramePacket()
→ ImageProcessor::processFrame()
→ 质心计算
→ 双相机配对
```

`CameraFrame` 已包含：

```cpp
quint64 frameId;
quint64 cameraTimestamp;
```

因此不修改 `CameraManager` 的采集回调、图像缓存和线程结构。

## 二、当前问题

当前代码在质心有效后，分别记录两台相机的首个有效质心帧：

```cpp
m_firstFrameId[cameraIndex]
```

并分别归一化：

```cpp
normalizedFrameId =
    frameId - m_firstFrameId[cameraIndex] + 1;
```

如果两台相机的第一个有效质心不来自同一次脉冲，例如：

```text
相机0首个有效帧：100
相机1首个有效帧：101
```

两者都会被归一化为 1，可能永久错一帧却仍被认为同步。

---

## 三、最小同步模型

在 `ImageProcessorWorker` 中新增：

```cpp
bool m_syncCalibrated = false;

quint64 m_firstRawFrameId[2] = {0, 0};
quint64 m_firstRawTimestamp[2] = {0, 0};

qint64 m_frameIdOffset = 0;
long double m_timestampOffsetTicks = 0.0L;

double m_estimatedFramePeriodTicks[2] = {0.0, 0.0};

quint64 m_lastRawFrameId[2] = {0, 0};
quint64 m_lastRawTimestamp[2] = {0, 0};
```

继续保留：

```cpp
quint64 m_droppedUnpairedSamples;
```

不拆成多个 UI 计数。

---

## 四、同步基准建立

在 `ImageProcessorWorker::processFrame()` 收到：

```cpp
frameId
cameraTimestamp
```

后，并且在质心有效性判断之前，记录每台相机的首个原始帧：

```cpp
if (frameId > 0 && m_firstRawFrameId[cameraIndex] == 0) {
    m_firstRawFrameId[cameraIndex] = frameId;
}

if (cameraTimestamp > 0 && m_firstRawTimestamp[cameraIndex] == 0) {
    m_firstRawTimestamp[cameraIndex] = cameraTimestamp;
}
```

当两路首个原始帧都已记录后，建立固定 FrameID 偏移：

```cpp
m_frameIdOffset =
    static_cast<qint64>(m_firstRawFrameId[1]) -
    static_cast<qint64>(m_firstRawFrameId[0]);
```

建立有符号时间戳偏移：

```cpp
m_timestampOffsetTicks =
    static_cast<long double>(m_firstRawTimestamp[1]) -
    static_cast<long double>(m_firstRawTimestamp[0]);
```

然后：

```cpp
m_syncCalibrated = true;
```

禁止继续使用“两台相机分别以首个有效质心帧归一化为 1”的方式。

---

## 五、FrameID 配对

在 `appendDifferentialSample()` 中，将两个队首样本转换到统一 FrameID：

```cpp
const qint64 alignedFrameId0 =
    static_cast<qint64>(front0.frameId);

const qint64 alignedFrameId1 =
    static_cast<qint64>(front1.frameId) - m_frameIdOffset;
```

配对规则：

```cpp
if (alignedFrameId0 < alignedFrameId1) {
    m_pendingCentroids[0].removeFirst();
    ++m_droppedUnpairedSamples;
    continue;
}

if (alignedFrameId1 < alignedFrameId0) {
    m_pendingCentroids[1].removeFirst();
    ++m_droppedUnpairedSamples;
    continue;
}
```

只有：

```cpp
alignedFrameId0 == alignedFrameId1
```

才进入时间戳校验。

同步尚未建立时：

```cpp
if (!m_syncCalibrated) {
    return false;
}
```

不要退回纯 FIFO 配对。

---

## 六、时间戳二次校验

FrameID 对齐后，计算有符号时间戳差：

```cpp
const long double signedDeltaTicks =
    static_cast<long double>(front1.cameraTimestamp) -
    static_cast<long double>(front0.cameraTimestamp);
```

扣除固定偏移：

```cpp
const long double residualTicks =
    signedDeltaTicks - m_timestampOffsetTicks;
```

时间戳残差用于发现：

- 错一整帧；
- 某一路漏触发；
- FrameID 对齐但曝光时刻异常。

---

## 七、帧周期估计

在 `processFrame()` 中分别估计两台相机时间戳周期：

```cpp
if (m_lastRawTimestamp[cameraIndex] > 0 &&
    cameraTimestamp > m_lastRawTimestamp[cameraIndex]) {

    const double dtTicks =
        static_cast<double>(
            cameraTimestamp - m_lastRawTimestamp[cameraIndex]);

    if (m_estimatedFramePeriodTicks[cameraIndex] <= 0.0) {
        m_estimatedFramePeriodTicks[cameraIndex] = dtTicks;
    } else {
        constexpr double alpha = 0.05;
        m_estimatedFramePeriodTicks[cameraIndex] =
            (1.0 - alpha) * m_estimatedFramePeriodTicks[cameraIndex]
            + alpha * dtTicks;
    }
}
```

随后更新：

```cpp
m_lastRawTimestamp[cameraIndex] = cameraTimestamp;
m_lastRawFrameId[cameraIndex] = frameId;
```

---

## 八、时间戳阈值

当两路都有有效周期估计时：

```cpp
const double referencePeriodTicks =
    std::min(m_estimatedFramePeriodTicks[0],
             m_estimatedFramePeriodTicks[1]);
```

初始阈值：

```cpp
const double timestampToleranceTicks =
    0.10 * referencePeriodTicks;
```

若：

```cpp
std::abs(residualTicks) <= timestampToleranceTicks
```

则允许配对。

若超限：

```cpp
if (residualTicks > 0) {
    m_pendingCentroids[0].removeFirst();
} else {
    m_pendingCentroids[1].removeFirst();
}

++m_droppedUnpairedSamples;
continue;
```

时间戳异常帧不得进入：

```cpp
m_differentialHistory
```

阈值保持为内部常量，不新增 UI 参数。

---

## 九、同步抖动

同步抖动改为基于时间戳残差：

```cpp
residualTicks =
    (timestamp1 - timestamp0) - timestampOffsetTicks;
```

不要继续对原始时间戳差先取绝对值。

向 UI 发送：

```cpp
emit syncSampleReady(residualUs);
```

UI 侧继续显示平均绝对抖动：

```cpp
syncJitterUs = std::abs(residualUs);
```

不新增 RMS、P95、最大值等 UI 项。

### 时间戳单位

禁止直接假设：

```cpp
deltaTicks / 1000.0
```

一定得到微秒。

优先读取或配置相机时间戳 tick 频率：

```cpp
residualUs =
    residualTicks * 1.0e6 / timestampTickFrequencyHz;
```

若当前无法确认 tick 频率：

- 内部继续使用 ticks；
- UI 显示 `同步抖动: 校准中` 或 `同步抖动: --`；
- 不要错误标注为 `μs`。


## 十一、重置条件

以下事件发生时必须重置同步状态：

- 开始新一轮采集；
- 停止后重新启动；
- ROI 切换；
- acquisition generation 改变；
- SDK 队列 flush；
- 相机断开或重连；
- 触发模式变化；
- 脉冲停止后重新启动。

重置内容：

```cpp
m_syncCalibrated = false;

m_firstRawFrameId[0] = 0;
m_firstRawFrameId[1] = 0;

m_firstRawTimestamp[0] = 0;
m_firstRawTimestamp[1] = 0;

m_frameIdOffset = 0;
m_timestampOffsetTicks = 0.0L;

m_estimatedFramePeriodTicks[0] = 0.0;
m_estimatedFramePeriodTicks[1] = 0.0;

m_lastRawFrameId[0] = 0;
m_lastRawFrameId[1] = 0;

m_lastRawTimestamp[0] = 0;
m_lastRawTimestamp[1] = 0;

m_pendingCentroids[0].clear();
m_pendingCentroids[1].clear();
m_differentialHistory.clear();
```

运行级重置时继续清零：

```cpp
m_lastPairedSerial = 0;
m_droppedUnpairedSamples = 0;
```

## 十二、测试要求

至少增加：

1. 两台相机 FrameID 起点不同但偏移固定，能够正确配对；
2. 相机0漏一个 FrameID 后能够恢复；
3. 相机1漏一个 FrameID 后能够恢复；
4. 两台相机第一个有效质心不在同一帧时，不再永久错位；
5. 固定时间戳偏移不计入同步抖动；
6. 时间戳残差接近一个帧周期时拒绝配对；
7. 正常小抖动下持续生成差分样本；
8. ROI 切换后同步状态和差分历史清空；
9. 同步未建立时不输出新的大气参数；
10. 单边队列长期积压时仍受 `historyWindowSize()` 限制。
