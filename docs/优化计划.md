# DIMM 项目优化计划

> 适用范围：仓库 `Tolight1/DIMM` 的 `src待优化` 目录  
> 目标读者：Codex / 代码维护者  
> 核心原则：**只做结构、重复代码、可维护性和局部性能优化，不改变现有业务行为。**

---

## 1. 总目标

本轮优化的主要目标：

1. 降低 `DIMM.cpp`、`DIMM.h`、`ImageProcessor.cpp`、`CameraManager.cpp` 等大文件的维护难度。
2. 合并职责过薄、仅做转发或简单赋值的 `Alignment*Controller/Coordinator`。
3. 消除重复的图像转换、阈值转换、配置解析和路径处理代码。
4. 使用结构化配置对象代替参数数量过多的回调。
5. 优化北极星识别和质心计算中的明确性能热点。
6. 让后续功能开发更容易定位模块、修改代码和编写测试。
7. 让 Codex 能够快速理解任务边界，避免一次性进行大范围重写。

---

## 2. 强制约束

以下约束优先级最高，任何阶段都必须遵守。

### 2.1 不修改 ROI 更新逻辑

不得改变以下行为：

- ROI 固定尺寸规则。
- ROI 位置计算规则。
- ROI 边界裁剪和硬件对齐规则。
- 双相机 ROI 配对提交规则。
- ROI 重居中触发条件。
- 质心丢失后切回全画幅的条件。
- 全画幅重新定位后切回 ROI 的流程。
- ROI 更新冷却时间、连续帧数和位移阈值含义。
- 相机硬件 ROI 的暂停、修改、恢复顺序。
- ROI 更新时脉冲、触发线和相机采集之间的现有时序。

以下函数及其调用顺序默认视为“受保护流程”，除非任务明确要求，否则不要修改其内部逻辑：

不允许：

- 修改调用顺序。

- 修改相机停止、ROI 设置、触发配置和重新启动的顺序。
- 将同步调用改成异步调用。
- 将双相机操作拆成可能产生不同步的独立流程。

### 2.2 不修改采集流程逻辑

不得改变以下行为：

- 相机连接、打开、启动、停止、关闭的顺序。
- 连续触发和外部触发配置顺序。
- 全画幅定位、硬件 ROI 跟踪、重新定位之间的状态转换。
- 双相机帧 ID 和时间戳配对规则。
- 硬件触发启动检查逻辑。
- 脉冲发生器启动、停止和切换频率的现有时序。
- 实时采集、模拟采集、暂停、对准模式之间的现有状态转换。
- 帧接收后的现有接受门控和 generation 过滤规则。
- 当前丢帧、未配对样本和统计计数的含义。

允许：

- 添加统计、日志和注释。
- 将纯计算函数移到独立模块。
- 为现有流程增加测试入口。

不允许：

- 修改同步模型。
- 修改帧队列策略。
- 修改信号连接方式。
- 修改跨线程调用方式。
- 修改帧复制、帧缓存或最新帧策略。

- 修改 acquisition generation 逻辑。

> 帧队列、双 Worker 并行处理、预览通道和测量通道分离等方案，本轮只记录为后续优化，不在本轮实施。

### 2.3 不进行构建

Codex 不需要执行任何构建操作。

禁止运行：


完成修改后只进行静态检查：

- 检查头文件包含关系。
- 检查声明和定义是否对应。
- 检查命名空间和类名是否一致。
- 检查明显的未使用参数。
- 检查是否存在重复定义。
- 检查是否误改受保护函数。
- 输出需要用户自行构建验证的内容。

由用户自行完成编译和硬件测试。

## 3. Codex 执行规则

每次只执行一个阶段或一个明确子任务，不要一次性重构整个项目。

每个任务开始前必须：

1. 阅读本文件。
2. 阅读目标文件的头文件和实现文件。
3. 搜索目标类的全部调用位置。
4. 确认是否涉及受保护的 ROI 或采集流程。
5. 若涉及受保护流程，只允许做完全等价的机械性提取。
6. 不主动修复任务范围之外的问题。
7. 不修改算法阈值、默认参数和状态含义。
8. 不进行全局格式化。

每个任务结束后必须输出：

```text
1. 修改摘要
2. 修改文件列表
3. 删除或合并的冗余代码
4. 是否触及 ROI 更新逻辑：否 / 仅机械性移动
5. 是否触及采集流程逻辑：否 / 仅机械性移动
6. 未构建说明
7. 用户需要手动验证的项目
8. 潜在风险
```

## 4. 优化优先级

### P0：低风险结构优化

优先执行：

1. 提取公共工具函数。
2. 引入统一常量和相机索引类型。
3. 拆分 `SettingsDialog`。
4. 建立结构化配置对象。
5. 合并过薄的 Alignment 状态转发层。
6. 增加必要注释和静态测试接口。

### P1：中等风险模块重构

在 P0 稳定后执行：

1. 建立真正拥有状态的 `AlignmentSession`。
2. 从 `DIMM` 提取结果写入模块。
3. 从 `DIMM` 提取配置应用模块。
4. 将质心质量判定统一到图像处理模块。
5. 减少 `DIMM.h` 暴露的内部状态。

### P2：局部性能优化

在结构稳定后执行：

1. 热像素模板缓存。
2. 星表三角形索引缓存。
3. 质心背景估计由排序改为直方图。
4. 高斯质心限制到局部窗口。
5. 减少全画幅找星的内存占用。

### 暂不实施

以下项目本轮不做：

- 双相机图像处理并行化。
- 帧队列架构重写。
- 信号槽线程模型调整。
- 测量通道和预览通道拆分。
- ROI 更新算法修改。
- 采集状态机重写。
- 相机 SDK 封装替换。
- UI 框架整体重写。
- 星图匹配算法整体替换。

# 6. 阶段二：统一相机数量与索引表达

## 6.1 目标

减少散落的魔法数字 `2` 和裸数组。

## 6.2 建议

新增：

```cpp
inline constexpr int kCameraCount = 2;

enum class CameraIndex : int {
    Camera1 = 0,
    Camera2 = 1
};
```

对于跨 Qt 信号槽的接口仍可保留 `int cameraIndex`，内部数据优先使用：

```cpp
std::array<T, kCameraCount>
```

## 6.3 本阶段限制

只允许机械性替换：

```cpp
T values[2];
```

改为：

```cpp
std::array<T, kCameraCount> values;
```

必须保持：

- 下标含义不变。
- 遍历顺序不变。
- 边界判断不变。
- Qt 信号参数类型不变。
- C 风格数组参数在涉及受保护流程时暂不修改。

## 6.4 不要一次性替换的内容

以下结构暂时保持原状，避免影响受保护流程：

```text
RoiRect rois[2]
RoiPosition positions[2]
RoiUpdatePauseState pauseState[2]
```

这些可在对应模块已经有单元测试后单独处理。

# 8. 阶段四：合并过薄的 Alignment 模块

## 8.1 当前问题

以下模块中存在较多薄封装：

```text
AlignmentController
AlignmentFlowCoordinator
AlignmentRuntimeCoordinator
AlignmentCandidateController
AlignmentManualSelectionController
```

典型问题：

- 只转发到 `PolarisTracker`。
- 只给 Runtime 字段赋值。
- 只返回固定字符串。
- 通过多个裸指针修改 `DIMM` 的内部状态。
- 文件数量增加，但状态所有权仍在 `DIMM`。

## 8.2 本阶段目标

先删除明显无价值的转发，不立即重写整个对准状态机。

## 8.3 建议处理

### `AlignmentFlowCoordinator`

建议拆分：

- 启动条件检查移到后续的 `AlignmentSession`。
- 状态文字移到 `AlignmentUiPresenter`。
- `actionForToggle` 在调用点直接表达。

完成后删除：

```text
AlignmentFlowCoordinator.h
AlignmentFlowCoordinator.cpp
```

### `AlignmentController`

建议：

- 直接转调 `PolarisTracker` 的函数删除。
- 状态变更函数保留时，统一命名为 `AlignmentStateTransitions`。
- 不要同时存在两层同义函数。

### `AlignmentRuntimeCoordinator`

建议暂时保留，但先将裸指针集合替换为完整状态对象。

不要继续增加：

```cpp
bool*
QPointF*
int*
qint64*
```

## 8.4 限制

- 不修改自动识别重试条件。
- 不修改人工确认流程。
- 不修改跟踪失败次数。
- 不修改 `ManualOnly`、`Tracking`、`RetryWaiting` 等状态含义。
- 不修改 solve generation。
- 不修改取消任务的时机。
- 不修改对准模式下相机预览流程。

## 8.5 验收条件

- 同一个状态变化只有一个实现位置。
- 不再存在仅一行转发的公开函数。
- UI 文本集中在 `AlignmentUiPresenter`。
- ROI 和采集流程无改动。

## 11.2 目标

建立统一质量结果：

```cpp
enum class CentroidQuality {
    Valid,
    InvalidCamera,
    EmptyImage,
    BelowThreshold,
    LowFlux,
    TooFewPixels,
    TooManyPixels,
    NearRoiEdge,
    EdgeSignal,
    OutOfFrame
};

struct CentroidMeasurement {

};
```

# 12. 阶段八：质心计算性能优化

## 12.1 直方图替代排序

当前背景估计需要把所有像素复制到 `std::vector<double>` 并排序。

对于 Mono8 图像，建议改为 256 桶直方图。

### 要求

- 截尾比例含义保持不变。
- 背景均值和方差计算结果应与旧算法接近。
- 先保留旧实现作为参考函数。
- 增加针对固定输入图像的结果对比测试。
- 不修改阈值策略。

建议误差范围：

```text
background 差异 <= 0.5 灰度级
threshold 差异 <= 1.0 灰度级
centroid x/y 差异 <= 0.05 px
```

### 回退条件

如果结果差异超过范围，保留旧算法，不切换默认路径。

## 12.2 高斯质心限制局部窗口

当前高斯加权在整个 ROI 上执行多轮 `exp()`。

建议：

1. 使用重心结果作为初值。
2. 在初值周围选择固定局部窗口。
3. 只在局部窗口内做高斯加权迭代。
4. 窗口超出边界时安全裁剪。

### 限制

- 不修改质心方法编号。
- 不修改默认迭代次数，除非单独说明。
- 不修改 ROI 尺寸。
- 不改变质心坐标为绝对坐标的转换逻辑。
- 必须保留旧实现用于对比。
